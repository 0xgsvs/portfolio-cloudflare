# Taste
- Keeps a close eye on the agent's todo list and expects it to stay accurate: tasks must be marked `completed` as they finish, with no stale `in_progress` items left behind (the user reads leftover `in_progress` entries as "paused" and calls them out). Confidence: 0.6
- Prefers to resolve a batch of problems incrementally, one issue at a time (e.g. "we will resolve them one by one") rather than having everything fixed in one sweep. Confidence: 0.5
- Uses Jujutsu (`jj`) for version control and expects commit descriptions authored via `jj describe`, written to the Conventional Commits specification (`feat:`, `fix:`, `refactor:`, `chore(deps):` etc., with a structured body). Confidence: 0.8
- Wants unrelated changes separated into their own commits — a feature, repo/infra tooling, and a dependency bump each belong in a distinct commit rather than one combined one — and is comfortable with the agent rewriting unpublished history (`jj split`, `jj describe -r`) to achieve it. Asks for follow-up fixes to land "in the next commit" rather than being folded into prior work. Confidence: 0.5
- Wants finished work committed immediately: as soon as a change is worthy of an atomic commit (feature added, fix done, anything finished), run `jj commit` with a proper Conventional Commits description so subsequent edits land on a new, empty working commit. Treat "done" as the trigger to commit, not a later cleanup step. Confidence: 0.75
- Expects every UI color — including focus rings and other incidental accents — to come from the project's established palette/design tokens. Calls out colors that are "out of place with the color theme" (e.g. a generic blue focus border) and wants them replaced with theme-consistent values rather than left as arbitrary picks. Confidence: 0.7
- Wants a "clean", borderless look: dislikes borders/outlines as focus indicators and asks for them to be removed entirely, favoring an in-theme fill/background inversion (matching existing hover states) over any visible ring. Confidence: 0.6
- Works from a modern terminal-first, keyboard-driven toolchain: Ghostty, Neovim, Helix, Zellij, zoxide, and Jujutsu (`jj`) with `jjui` — expects those tools represented when listing their own tooling. Browsing is also keyboard/Vim-driven (Vimium extension, e.g. `r` to refresh), so expects the agent to reason about the site from that interaction model. Confidence: 0.6
- Impatient with long silent stretches: when the agent spends a long time reading/exploring before producing anything, they check in ("its been 27min are you stuck or what?"). Wants the agent to move to building/acting quickly and to surface intermediate progress rather than going dark on research. Confidence: 0.55
- Expects grouped UI lists/categories to be colour-coded rather than left neutral, and to reuse the palette already applied to analogous components elsewhere on the site (e.g. complained that new role sections "have no colors" and expected one hue per group like the home stack chips). Confidence: 0.55
- Reaches for VitePress when a documentation site is needed, and wants docs served from its own subdomain at the root (`docs.<domain>`) — as a separate Cloudflare Pages project pointed at a `docs/` folder inside the existing site repo, rather than a path-based route or a separate repo. Confidence: 0.5
- Expects local dev servers to actually be reachable from their browser: `dev`/`preview` script commands should bind all interfaces (e.g. `--host 0.0.0.0`), not the framework default `localhost` (which on their machine resolves to IPv6 loopback only, so nothing connects). New scripts should follow the host convention the project's existing scripts already use. Confidence: 0.6
- Expects the agent to verify framework/tool usage against the official documentation ("do you have the vitepress docs?") rather than inventing or leaning on undocumented behaviour; the docs' LLM-friendly `.md` page variants are the preferred source. Confidence: 0.45
- Audits stray/generated artifacts in the repo: questions files that appeared unexpectedly and wants them justified by actual usage ("do we need them where are they used?") rather than assumed useful — happy to delete them once shown nothing references them. Confidence: 0.4
- Expects graphic elements (portrait/avatar, commit-calendar grid) to be visually centred within their containing section rather than hugging one edge — reports left-aligned visuals with dead space beside them as a defect to be fixed. Confidence: 0.4
- Dislikes harsh, high-contrast color flips (e.g. a black fill with yellow text where the user "type[s] it in yellow" felt "too high contrast"). Prefers softer, subtler treatments that stay within the same hue family instead of inverting to opposite extremes. Confidence: 0.55
